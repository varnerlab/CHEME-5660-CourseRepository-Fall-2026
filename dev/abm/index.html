Thermal minority game

VLQuantitativeFinancePackage.MyThermalMinorityGameModel — Type
mutable struct MyThermalMinorityGameModel <: AbstractAgentModel

A minority game with N agents in which each agent chooses among its policies with Boltzmann (softmax) probabilities set by a temperature.

Each round, every agent chooses buy ($+1$) or sell ($-1$). The attendance is $A_{t}=\sum_{i}a_{i,t}$, and agents on the minority side, $-\text{sign}(A)$, win. Every agent sees the same information $\mu_{t}\in\{1,\dots,P\}$, with $P=2^{m}$, and holds $J$ policies; policy $\pi_{ij}$ is a lookup table that maps each $\mu$ to an action $\pi_{ij}(\mu)\in\{-1,+1\}$.

Fields

  • N::Int: number of agents (odd, so $A_{t}$ is never zero).
  • m::Int: memory, the number of past minority actions in the information; $P=2^{m}$.
  • J::Int: number of policies per agent.
  • temperature::Float64: the temperature of the Boltzmann choice rule (dimensionless, in units of the score). 0.0 gives the best-scoring policy, Inf a uniform choice.
  • information::Symbol: :history (the last m minority actions) or :random ($\mu$ drawn uniformly each round).
  • policies::Array{Int8,3}: actions $\pi_{ij}(\mu)\in\{-1,+1\}$, sized N×J×P.

Scores use the binary-model normalization of Challet, Marsili, and Zecchina (2000), $U_{ij,t+1}=U_{ij,t}-\pi_{ij}(\mu_{t})A_{t}/P$, so the temperature here is measured in those units.

VLQuantitativeFinancePackage.boltzmann_weights — Function
boltzmann_weights(scores::AbstractVector{<:Real}, temperature::Real) -> Vector{Float64}

Return the Boltzmann (softmax) probabilities $p_{j}=\exp(U_{j}/T)/\sum_{k}\exp(U_{k}/T)$ for the scores $U_{j}$ at temperature $T$. These maximize the entropy $-\sum_{j}p_{j}\ln p_{j}$ for a fixed expected score.

At temperature = 0 the probability is shared equally among the highest scores; at temperature = Inf it is uniform. Throws an ArgumentError for a negative or NaN temperature.

VLQuantitativeFinancePackage.build — Method
build(modeltype::Type{MyThermalMinorityGameModel}, data::NamedTuple) -> MyThermalMinorityGameModel

Build a thermal minority game and draw every agent's policies at random: each entry $\pi_{ij}(\mu)$ is $+1$ (buy) with probability buy_probability and $-1$ (sell) otherwise.

Arguments

  • data::NamedTuple with keys N::Integer (odd, ≥ 1), m::Integer (1 to 20), and optional J::Integer = 2 (≥ 2), temperature::Real = 0.0 (≥ 0, Inf allowed), information::Symbol = :history (or :random), buy_probability::Real = 0.5 (0 to 1; 0.5 draws buy and sell equally, as in the standard game), and rng::AbstractRNG = Random.default_rng().

Throws an ArgumentError for invalid inputs, including the retired key S (use J).

VLQuantitativeFinancePackage.solve — Method
solve(model::MyThermalMinorityGameModel; number_of_rounds::Int, burn_in::Int = 0,
    rng::AbstractRNG = Random.default_rng(), initial_information = nothing) -> NamedTuple

Play the minority game for burn_in + number_of_rounds rounds and return the last number_of_rounds.

Each round: every agent draws a policy with boltzmann_weights of its scores, takes that policy's action for the current information $\mu_{t}$, the attendance $A_{t}=\sum_{i}a_{i,t}$ is formed, and every policy's score is updated as $U_{ij,t+1}=U_{ij,t}-\pi_{ij}(\mu_{t})A_{t}/P$. With information = :history, the new minority action $-\text{sign}(A)$ becomes the lowest bit of the next $\mu$.

Arguments

  • number_of_rounds::Int: rounds to return (≥ 1).
  • burn_in::Int = 0: rounds played first and discarded (≥ 0).
  • rng: random number generator.
  • initial_information: $\mu_{0}$ for the first round, $t=0$ (1 to $P$); drawn at random if nothing.

Returns

A NamedTuple with attendance::Vector{Int} and information::Vector{Int} for the returned rounds, volatility_per_agent::Float64 $=\langle A^{2}\rangle/N$ over those rounds (1 for independent coin-flipping agents), alpha::Float64 $=P/N$, and final_scores::Matrix{Float64} (N×J).

Farmer–Joshi market

VLQuantitativeFinancePackage.MyFarmerJoshiMarketModel — Type
mutable struct MyFarmerJoshiMarketModel <: AbstractAgentModel

The agent-based market of Farmer and Joshi (2002), "The price dynamics of common trading strategies", J. Econ. Behav. Organ. 49, 149–171. Value investors and trend followers trade through a market maker who moves the log price $\ln S_{t}$ in proportion to the net order.

Each trader uses a state-dependent threshold strategy (the paper's Section 3.2.4): a position of size $c=a(T-\tau)$ is entered when a signal crosses the entry threshold $T$ and held until it crosses the exit threshold $\tau$ (see threshold_position).

Fields

  • a::Float64, λ::Float64: capital scale and liquidity (shared).
  • σ_S::Float64: annualized volatility of the price noise, so the noise in $\ln S_{t+1}$ is $\sigma_S\sqrt{\Delta t}\,Z_{t+1}$.
  • σ_v::Float64, μ_v::Float64: annualized volatility and drift of the reference log value, so $v_{t+1}=v_{t}+\mu_v\Delta t+\sigma_v\sqrt{\Delta t}\,Z'_{t+1}$.
  • Δt::Float64: the time step in years (1/252 for one trading day).
  • value_entry, value_exit, value_capital, value_offset::Vector{Float64}: each value investor's entry threshold $T$, exit threshold $\tau$, position size $c$, and offset $v^{(i)}$ of its perceived log value from the reference $v_{t}$.
  • trend_entry, trend_exit, trend_capital::Vector{Float64} and trend_lag::Vector{Int}: each trend follower's thresholds, position size, and lag $\theta$ (time steps).

VLQuantitativeFinancePackage.threshold_position — Function
threshold_position(current::Float64, signal::Float64, entry::Float64, exit::Float64,
    capital::Float64, direction::Int) -> Float64

Return a trader's next position under the threshold strategy of Farmer and Joshi (2002), Section 3.2.4. The position is $-c$, $0$, or $+c$ with $c=$ capital.

  • Value investor (direction = -1), signal = mispricing $m=\ln S_{t}-v_{t}^{(i)}$: from zero, go short if $m>T$ and long if $m<-T$; exit a short when $m<\tau$ and a long when $m>-\tau$.
  • Trend follower (direction = +1), signal = $\ln S_{t}-\ln S_{t-\theta}$: from zero, go long if the signal is above $T$ and short if below $-T$; exit a long when it falls below $\tau$ and a short when it rises above $-\tau$.

All comparisons are strict. Here $T=$ entry and $\tau=$ exit.

build(modeltype::Type{MyFarmerJoshiMarketModel}, data::NamedTuple) -> MyFarmerJoshiMarketModel

Build a Farmer–Joshi market and draw each trader's thresholds, offset, and lag. Defaults are the paper's Table 1.

Arguments (all optional)

  • Per group, with prefix value_ or trend_: number = 1200, T_min = 0.2, T_max = 4.0, τ_min = -0.2, τ_max = 0.0, a = 2.5e-3. Entry thresholds $T$ are uniform on [T_min, T_max], exit thresholds $\tau$ uniform on [τ_min, τ_max], and $c=a(T-\tau)$.
  • value_v_min = -2.0, value_v_max = 2.0: range of the perceived-value offsets.
  • trend_θ_min = 1, trend_θ_max = 100: range of the integer lags.
  • Shared: Δt = 1/252 (years), σ_S = 0.35*sqrt(252) (the paper's 0.35 per step), λ = 1.0, σ_v = 0.16, μ_v = 0.0, rng = Random.default_rng(). σ_S and σ_v are annualized (units 1/√yr). The paper drives the reference value with a data path in its Table 1 run; σ_v and μ_v are used only when solve is not given log_value_path.

VLQuantitativeFinancePackage.solve — Method
solve(model::MyFarmerJoshiMarketModel; number_of_steps::Int, burn_in::Int = 0,
    rng::AbstractRNG = Random.default_rng(), initial_log_price::Float64 = 0.0, v₀::Float64 = 0.0,
    log_value_path = nothing) -> NamedTuple

Simulate the market for burn_in + number_of_steps steps and return the last number_of_steps. Each step, in order:

  1. every trader sets its next position $x_{t+1}^{(i)}$ from $\ln S_{t}$ (and $v_{t}$) with threshold_position;
  2. its order is $\omega_{t+1}^{(i)}=x_{t+1}^{(i)}-x_{t}^{(i)}$ (Eq. 1);
  3. the market maker sets $\ln S_{t+1}=\ln S_{t}+\lambda^{-1}\sum_{i}\omega_{t+1}^{(i)}+\sigma_S\sqrt{\Delta t}\,Z_{t+1}$ (Eq. 7 with $\xi_{t+1}=\sigma_S\sqrt{\Delta t}\,Z_{t+1}$);
  4. the reference log value advances, $v_{t+1}=v_{t}+\mu_v\Delta t+\sigma_v\sqrt{\Delta t}\,Z'_{t+1}$ (Eq. 13), or is read from log_value_path.

A value investor perceives $v_{t}^{(i)}=v_{t}+v^{(i)}$ (Eq. 18). A trend follower holds no position until $t\geq\theta$.

Arguments

  • initial_log_price = 0.0: the starting log price $\ln S_{0}$ (0.0 normalizes $S_{0}=1$).
  • v₀ = 0.0: the starting reference log value $v_{0}$, used when log_value_path is not given.
  • log_value_path: optional reference log values $v_{0},v_{1},\dots$; its length must be at least burn_in + number_of_steps + 1.

Returns

A NamedTuple with log_price and log_value (number_of_steps + 1 values), returns $=\ln S_{t+1}-\ln S_{t}=g_{t+1}\Delta t$ (number_of_steps values; divide by $\Delta t$ for the growth rates), and value_volume and trend_volume, the total absolute order $\sum_{i}|\omega_{t+1}^{(i)}|$ of each group per step.
