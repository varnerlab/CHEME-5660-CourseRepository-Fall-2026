Open an Alpaca paper account

Needed for: the practicum (required), and the L14a paper trading example (optional)
Cost: free
Time: about 20 minutes

Alpaca is a brokerage built for programs that trade. A paper account at Alpaca trades simulated money at real market prices, so you can test a trading method before it risks real money. You need your own paper account for the practicum.

A program sends its requests to Alpaca through Alpaca's RESTful API. Alpaca identifies the program by two keys, an API key ID and a secret key, and every request carries both. Our Julia package, the Alpaca SDK, builds and sends these requests.

Step 1: Open a paper account

  1. Go to app.alpaca.markets/signup, and sign up with your email address. Anyone, in any country, can open a paper-only account.
  2. Confirm your email address if Alpaca sends you a confirmation link.
  3. Your paper account starts with 100,000 USD of simulated money. You do not deposit any real money.

Step 2: Generate your paper API keys

  1. Sign in to the Alpaca dashboard, and open your paper account.
  2. In the API Keys panel of the Home page, select Generate New Keys.
  3. Copy the API key ID and the secret key right away. Alpaca shows the secret key only once. If you lose the secret key, generate a new pair of keys.

Paper keys work only with your paper account. The keys of a live account do not work with a paper account.

Step 3: Store your keys in a credentials file

The Alpaca SDK and the L14a MCP server read your keys from a credentials file, not from a notebook. A key typed into a notebook goes to everyone who gets a copy of the notebook. The credentials file stays on your computer.

  1. Download and unzip the Week 14 release from the course releases page, and open its lectures/week-14/L14a/alpaca-mcp/conf folder.
  2. Copy apidata-template.toml to a new file named apidata.toml in the same folder.
  3. In apidata.toml, replace the text between the quotes on the key and secret lines with your API key ID and secret key, and save the file.

Keep the quotes, and leave the endpoint line as it is. The [Credentials] section of the finished file looks like this, with your own keys in place of the example keys: 

[Credentials]
endpoint = "https://paper-api.alpaca.markets/v2"
key      = "PKABCDEFGHIJKLMNOPQRSTUVWX"
secret   = "abcdefghijklmnopqrstuvwxyz0123456789ABCDEFGH"

Step 4: Check your keys with the Alpaca SDK

  1. Open a terminal in the Week 14 folder, the folder that holds Project.toml. Install the course packages, including the Alpaca SDK, with this command. The first installation takes several minutes. 
    julia --project=. -e "import Pkg; Pkg.instantiate()"
  2. Start Julia in the same folder with julia --project=., and run these three lines: 
    using Alpaca
client = load_client("lectures/week-14/L14a/alpaca-mcp/conf/apidata.toml")
account = api(client, MyAccountEndpointModel())

The account table shows the cash and the buying power of your paper account. The SDK documentation shows how to read prices and place orders in the same way.

Step 5 (optional): Talk to your paper account in Claude Code

In the L14a example, we'll ask about the paper account and place orders in plain English. Claude Code turns each request into calls to Alpaca's API through a Model Context Protocol (MCP) server, a program in the alpaca-mcp folder that offers one tool for each Alpaca endpoint.

  1. Install Claude Code. Claude Code needs a Claude plan or a Claude Console account.
  2. Open a terminal in the lectures/week-14/L14a/alpaca-mcp folder, and run claude.
  3. Claude Code asks whether to use the alpaca server. Choose Use this MCP server, and type /mcp to check that the server is connected.
  4. Ask a question, for example: Is the market open? How much cash does my paper account have?

The server works only with the paper endpoint, and the language model never sees your keys.

Keep your keys private

Treat your keys like a password. Anyone with your keys can trade in your paper account.

  • Do not paste your keys into a notebook, a Canvas submission, or a discussion post.
  • Do not share your keys with classmates. Each student needs their own paper account.
  • Do not commit apidata.toml to GitHub. The .gitignore file in the conf folder already tells git to skip it.

If you think your keys were exposed, generate new keys in the API Keys panel, and paste the new keys into apidata.toml.

If the check fails

The error message says what to fix. The most common problems are:

  • credentials file not found. The file must be named exactly apidata.toml and sit in the conf folder. On Windows, check that the editor did not save it as apidata.toml.txt.
  • AlpacaError(status=401, ...): unauthorized. Alpaca does not accept the keys. Check that you copied the paper keys, without spaces before or after them. If you lost the secret key, generate new keys.
  • This server trades only in a paper account. The MCP server found another endpoint in the file. Copy the endpoint line from apidata-template.toml again.

If you are still stuck, come to office hours. Describe the error message, but do not share your keys.
